## 3. 포함 판단

### 3.1 `celery/celery` — 라이선스 수동 확인 후 포함

- GitHub API는 `license.spdx_id = NOASSERTION`을 준다. 스크립트는 이를 `LICENSE_NOT_PERMISSIVE:NOASSERTION`으로 제외했다.
- `LICENSE` 파일을 직접 확인했다 (2026-09-11, `main` 브랜치):
  - 코드: "The BSD License (3 Clause)" 선언과 BSD-3-Clause 조항 전문
  - 추가 절 "Documentation License": `docs` 디렉터리의 렌더링된 문서는 **CC BY-SA 4.0**
  - GitHub 탐지기가 NOASSERTION을 낸 이유는 이 복수 라이선스와 머리말 때문으로 보인다 (추정)
- **판단:** 코드는 BSD-3-Clause다. ADR-007·011의 permissive 조건을 충족하므로 포함한다. `repo_license`는 `BSD-3-Clause`로 기록한다.
- **조건:** celery의 `docs/` 경로에서 나온 레코드는 데이터셋 스니펫에서 빼야 한다.
  CC BY-SA의 동일조건 변경허락은 CC BY 4.0 데이터셋(ADR-011)과 맞지 않는다.
  파이프라인 경로 필터(§4.2 ②, 재헌)에서 뺄지, 데이터셋 내보내기(§4.2 ④, `datasets/export/`, 성제)에서 뺄지 정해야 한다 (§5 ⑦).

**지표:** 스크립트는 celery를 라이선스 단계에서 걸렀기 때문에 PR·이슈 지표를 재지 않았다.
같은 함수 `evaluate_repo`에 라이선스만 수동 확인값으로 덮어써 따로 쟀다 (2026-09-11 실행, API 33회).

- 커밋 13,252 / pr_ratio 0.967 / issue_ref_ratio 0.500 / 표본 30 / 점수 **0.7654**
- 후보 43개 사이에 넣으면 12위다 (home-assistant 0.7700과 keras 0.7499 사이). 점수로도 들어올 저장소였다.
- 원 CSV와 측정 창이 하루 다르다 (CSV는 since 2025-09-10, celery는 since 2025-09-11). 결과를 바꿀 수준은 아니다.
- CSV에 celery 행은 넣지 않았다. CSV는 스크립트 출력 원본으로 둔다 (손으로 고치면 재현이 깨진다).

재현:
```bash
python - <<'EOF'
import os
from pathlib import Path
from pipeline import select_repos as sr
sr.load_env_file(Path(".env"))
client = sr.GitHubClient(os.environ["GITHUB_TOKEN"], sr.resolve_cache_dir(None))
item = client.get_json("/repos/celery/celery")
item["license"] = {**(item.get("license") or {}), "spdx_id": "BSD-3-Clause"}  # 수동 확인값
print(sr.evaluate_repo(client, "celery/celery", since=sr.since_iso(365), sample_size=30, item=item))
EOF
```

### 3.2 `encode/httpx` — 포함, 비율 신뢰도 낮음

- CSV 36위, 점수 0.5215 (pr 1.000, issue_ref 0.000). **표본 6건**: 최근 1년 사람 커밋(병합·봇 제외)이 6건뿐이다.
- 6건에서 나온 비율의 95% 신뢰구간(Wilson): pr_ratio 6/6 → **0.61~1.00**, issue_ref_ratio 0/6 → **0.00~0.39**.
  표본 30건인 저장소의 pr 30/30 → 0.89~1.00과 비교하면 폭이 3배 이상이다. 표에 적힌 1.000·0.000을 그대로 믿으면 안 된다.
- **점수로는 들어올 수 없는 저장소를 판단으로 넣었다.** 점수 0.5215는 채움 경계(0.6691)보다 한참 아래다.
- 포함 근거:
  - §4.3 초기 후보 예시다. 팀이 킥오프 전에 적어 둔 저장소다.
  - 최근 1년 커밋이 적다는 건 **지금** 활동이 적다는 뜻이다. 과거 삭제 이력이 없다는 뜻이 아니다 (커밋 1,523개, 2019년 생성).
    채굴은 전체 이력을 대상으로 하므로, 최근 1년 표본이 작다는 사실이 곧 채굴 가치가 낮다는 뜻은 아니다.
  - 크기가 8MB라 넣는 비용이 거의 없다.
- issue_ref 0/6 — 이슈 참조가 하나도 없었다. 이유 회수는 PR 본문에 기대야 할 가능성이 크다.
