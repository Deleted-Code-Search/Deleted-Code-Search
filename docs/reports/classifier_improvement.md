## 2. 원인: "이유 있음 vs UNK" 혼동

게이트 2 혼동 행렬(`gate2_test.md` §3)에서 틀린 40건을 나누면 다음과 같다.

| 틀린 유형 | 건수 | 내역 |
|---|---:|---|
| 정답 UNK → 이유로 예측 | 15 | DESIGN 11, FEAT 3, DEAD 1 |
| 정답 이유 → UNK 로 예측 | 11 | DEAD 4, DESIGN 4, LIB 2, FEAT 1 |

그래서 고칠 곳을 둘로 봤다. 채점이 비슷한 이유끼리의 차이까지 벌하는지(개선 1), 분류기가 UNK 를 더 잘 가르게 할 수 있는지(개선 2·3)다.

## 3. 개선 1: 채점 기준 (분류기 답은 그대로)

분류기의 답을 한 글자도 바꾸지 않고 정답 인정 범위만 넓혔다. 이유 8종 체계와 `DeletionRecord` 스키마는 그대로이고, 묶음은 채점에만 쓴다.

| 묶음 | 라벨 | 뜻 |
|---|---|---|
| 고침 | BUG, PERF, SEC | 버그·성능·보안 문제를 고치려고 지웠다 |
| 정리 | DEAD, DESIGN, FEAT | 안 쓰는 코드·구조 변경·기능 제거로 지웠다 |
| 교체 | LIB | 라이브러리로 바꾸며 지웠다 |
| 모름 | UNK | 이유를 알 수 있는 근거가 없다 |

| 채점 | 정확도 | 기준선 A | 기준선 B | 전부 UNK |
|---|---:|---:|---:|---:|
| 8종, 확정 라벨만 (게이트 2) | 60.0% | 33.0% | 38.0% | 50.0% |
| 4묶음, 확정 라벨만 | 69.0% | 39.0% | 50.0% | 50.0% |
| 8종, 라벨러 둘 중 하나 일치 | 69.0% | 45.0% | 42.0% | 67.0% |
| **4묶음 + 라벨러 둘 중 하나 일치** | **78.0%** | 51.0% | 54.0% | 67.0% |

- 관대 채점은 **바닥도 함께 올린다.** 전부 UNK 가 50.0% → 67.0% 다. 바닥과의 차이는 10%p → 11%p 로 거의 그대로이므로, 60 → 78 은 분류기가 나아진 양이 아니다
- 묶음은 test 결과를 보고 정했다. 정답이 UNK 가 아닌 50건 중 45건이 정리 묶음에 든다

## 4. 개선 2: 분류기 변경

규칙 r1 + scikit-learn 모델 m2 + LLM 합산 구조에서 LLM 부분을 바꿔 봤다. 기록은 `stage2.md` §3 이다.

- **프롬프트 c4** = c3 + 라벨링 가이드의 UNK 판단 기준 (§5·§6.2.1·§6.3.1)
- **모델** = deepseek-v4.1-flash → `nvidia/nemotron-3-ultra-550b-a55b`(550B)
- **sklearn 점수 제외.** nemotron 에 m2 점수를 더하면 오히려 내려갔다 (8종 65.0% / 4묶음 77.0%). LLM 합산 가중치가 flash 답에 맞춰 고른 값이기 때문으로 본다

| 설정 | 8종 strict | 4묶음 lenient |
|---|---:|---:|
| flash + c4, LLM 단독 | 60.0% | 78.0% |
| **nemotron + c4, LLM 단독 — `nemotron+c4`** | **70.0%** | **80.0%** |
| nemotron + c4, m2 합산 | 65.0% | 77.0% |

가장 큰 변화는 모델 교체다. 같은 flash 에서 c4 만 넣어서는 거의 움직이지 않았다.

## 5. 개선 3: 다수결

**새 분류기 버전 `vote3+c4`** — 세 답의 다수결이고, 셋 다 갈리면 UNK 다. 모두 프롬프트 c4 의 LLM 단독 답이다.

1. flash (온도 0)
2. nemotron (온도 0)
3. nemotron 3회 다수결 (온도 0.7, 셋 다 갈리면 UNK)

**8종 73.0% / 4묶음 85.0%** 다. 게이트 2 예측과 짝 비교(한쪽만 맞힌 건, 정확 이항 검정)는 8종 19건 : 6건 (p = 0.015), 4묶음 11건 : 4건 (p = 0.118)이다. 이 p 값은 여러 설정 중 고른 것을 보정하지 않았다.

보고서 안 이름과의 대응: `vote3+c4` = `massage/vote:s1+s3+s6`, `nemotron+c4` = `massage/s3:llm-only`. 두 이름 모두 기존 `r1+m2`, `r1+m2+c3` 와 겹치지 않으며, 데이터셋의 `classifier_version` 에는 들어가지 않았다 (§7).

## 7. 한계

- **test 100건을 보며 설정을 골랐다.** 사전 등록의 "개선 시도는 test 가 아닌 새 표본에서만 한다"(`docs/evaluation.md`)를 따르지 않은 것이다. 묶음·프롬프트·모델·다수결 구성을 모두 test 결과를 본 뒤 정했고, `vote3+c4` 는 이름 46개 중 가장 높은 하나다. **새 데이터에서는 더 낮을 것으로 봐야 한다.** 새 표본 측정은 하지 않았다
- **100건이라 구간이 넓다.** 다수결의 95% 구간이 8종 63.6~80.7%, 4묶음 76.7~90.7% 다. 온도 0.7 답이 섞인 설정 사이의 1~3%p 차이는 우연과 구별되지 않는다
- **데이터셋 72만 건의 라벨은 기존 분류기 그대로다.** `dataset-v0.9` 의 FULL_FUNCTION 723,087건은 사람 확정 500 + `r1+m2+c3` 표본 2,891 + `r1+m2` 249,247 + 이유 미구분 470,449 다. `vote3+c4` 는 건당 5회 호출이라 전체에는 약 360만 회(723,087 × 5)가 필요해 무료 API 로 돌릴 수 없다. 적용은 향후 과제다. 데이터셋에서 이 문서의 73.0%·85.0% 를 인용하면 안 된다
- **버린 시도**
  - **few-shot(c5, train 예시 10건):** 같은 모델의 c4 보다 낮았다. nemotron LLM 단독 8종 65.0% / 4묶음 74.0%, flash 59.0% / 76.0%
  - **API 없이 예측 섞기(규칙 26개):** 4묶음을 78.0% 위로 올린 규칙이 없다. 기준선 B 를 믿고 UNK 를 뒤집는 규칙은 58.0% 까지 떨어졌다
  - **mistral-large-4(1T):** 호출 24건이 모두 300초 시간 초과라 30분 규칙으로 멈췄다. 결과가 아니다
