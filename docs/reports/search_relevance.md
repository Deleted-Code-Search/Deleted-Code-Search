# 검색 관련성 판정 절차 — Precision@10 (#193)

CHARTER §9 8주차 산출물 "Precision@10 보고", §10 목표 P@10 ≥ 0.6·기준선(키워드) 대비 우위.
도구는 `eval/search_relevance.py`. **판정은 사람이 한다** — 도구·모델은 판정 칸을 채우지 않는다 (ADR-005).

**상태: 전체 임베딩 뒤 시트를 뽑는다. 아직 판정 전.**

## 절차

1. 전체 임베딩(`python -m search.embed`)과 키워드 색인이 같은 데이터셋(`dataset-v0.9`)인지 확인한다.
2. `python -m eval.search_relevance export` →
   - `docs/reports/search_relevance_sheet.csv` — **블라인드 시트**
   - `docs/reports/search_relevance_key.json` — **키**. 판정이 끝날 때까지 열지 않는다.
3. 판정자 두 명이 각자 시트의 자기 칸을 채운다. 상대 칸은 보지 않는다.
   - 성제 → `relevant_sj`, 희수 → `relevant_hs`
   - 값: `1`(관련) / `0`(무관). y/n, o/x 도 받는다.
4. `python -m eval.search_relevance score`
   - 판정자별·모드별 P@10(질의별 평균)과 MRR을 낸다.
   - 두 칸이 다 차면 일치율, Cohen's kappa, 두 사람 평균도 낸다.
   - 한 사람 칸이 일부만 차 있으면 멈춘다. 빈칸 수를 알려 준다.

## 블라인드 시트

- **모드·순위 칸이 없다.** 판정자는 어느 쪽 결과인지 모른다 (#194 희수 리뷰).
- 질의마다 keyword 상위 10개와 semantic 상위 10개를 합친다.
  - 같은 레코드는 한 번만 넣는다.
  - 고정 시드(`SEED`)로 섞은 순서로 둔다. 응답 순서는 남기지 않는다.
- `code` 칸: 지워진 함수 본문. 판정자가 함수가 뭘 하는지 보고 판단하라는 칸이다.
  - 길면 앞 40줄(3,000자 이내)과 `… (앞부분만, 전체 N줄)` 표시.
  - `LINK_ONLY` 는 라이선스로 코드를 내보내지 않는다 — `(라이선스로 코드 미제공 - source_url 에서 확인)`.
    `source_url`(GitHub 커밋 주소)에서 본다.
- 어느 모드 몇 위인지는 키에만 있다. `score` 가 키로 다시 모드별로 나눈다.
- 레코드에서 온 텍스트(커밋 첫 줄·함수 이름·경로)가 `= + - @` 로 시작하면 앞에 `'` 를 붙인다.
  스프레드시트가 수식으로 읽지 않게 하려는 것이다.
- P@10 의 분모는 늘 10 이다.
  - 결과가 10개보다 적으면 모자란 칸은 무관으로 센다. 키워드 검색이 0건이면 0이다.
  - 키나 시트에 질의가 빠져 있으면 `score` 는 거부한다. 남은 질의만으로 평균하지 않는다.
  - 키의 질의 문장이나 키워드 낱말이 지금 `QUERIES` 와 다르면 거부한다. 낱말만 바뀌어도 keyword 결과가 달라진다.

## 질의 (10개 = 자연어 8 + 코드 조각 2)

- 의미 검색에는 문장을 그대로 넣는다.
- 키워드 검색에는 사람이 고른 같은 뜻의 낱말을 넣는다. 키워드 쪽에 유리한 설정이다.
- 질의 목록은 `eval/search_relevance.py` 의 `QUERIES` 에 있다.
- 모델을 고를 때 쓴 질의 10개(`eval/embedding_bench.py`)와 겹치지 않는다.

**빼고 바꾼 질의: `def load_config(path): … yaml.safe_load(f)`**

- 처음 질의 목록에 있었다. 이 질의는 시연 예시로 고른 것이다.
  - 표본 임베딩 화면에서 같은 이름의 지워진 함수 둘이 1·2위로 나오는 것을 보고 골랐다.
  - 결과가 좋은 것을 보고 고른 질의라, 평가에 넣으면 의미 검색 쪽으로 치우친다 (#194 희수 리뷰).
- 대신 넣은 질의는 `def chunks(items, size): … yield items[i:i + size]` 이다.
  - 결과를 보지 않고 정했다. 키워드 검색 낱말은 `chunks`.
- `load_config` 는 시연 예시(검색 탭)에는 그대로 둔다.

## 한계

- 질의 10개다. §10.3 의 30개(자연어 15 + 코드 15)보다 적다. 8주차 1차 측정이다.
- 판정자 두 명 중 한 명(성제)은 의미 검색 작성자다. 블라인드 시트로 모드를 가렸지만 질의는 작성자가 골랐다.
- 하이브리드(임베딩 + 키워드)는 이번 범위가 아니다 (ADR-023).
