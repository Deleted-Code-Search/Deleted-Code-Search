# 분류기 근거 등급 - EXPLICIT 을 가이드 v3 로 바꾸려다 버린 기록 (#178)

- 작성: 2026-10-18, 희수(hs). 숫자 원본: `docs/reports/classifier_grade_v3.json`
- **결정 (2026-10-18, 조장): 등급 규칙은 r1 을 유지한다.** 시도한 r2 는 쓰지 않는다. r2 코드는 커밋 `85deff9` 에 있고 다음 커밋에서 되돌렸다
- 남긴 것: 평가 도구의 근거 등급 지표(`classify/evaluate.py`), 게이트 2 test 라벨 불변 테스트(`tests/test_classifier.py::test_classifier_reproduces_the_gate2_test_labels`)

## 1. 왜 손댔나

분류기(`r1+m2+c3`)가 EXPLICIT 을 거의 내지 못한다. test 100 에서 0건(정답 24), 검증 100 에서 2건(정답 21)이다 (`gate2_test.md` §4, `classifier_val.md` §4).

r1 은 EXPLICIT 을 "고른 라벨과 **같은 키워드**의 문장이 **함수 이름**을 가리킬 때" 만 준다. 학습 300건의 정답 EXPLICIT 65건으로 보면:

| | 건수 |
|---|---:|
| 정답 인용문이 우리 맥락 문장 안에 있다 | 46 |
| 인용문의 키워드 라벨이 정답 라벨과 같다 (r1 첫 조건) | **8** |
| 인용문에 키워드가 없다 / 다른 이유 키워드다 | 35 / 22 |
| 인용문이 함수 이름을 가리킨다 (r1 둘째 조건) | **6** |
| 인용문이 파일 이름 / 디렉터리·모듈 낱말을 가리킨다 | 13 / 26 |

## 2. 시도한 것 - r2

- **E2** (가이드 v3 §6.4.5): 함수 이름(r1 과 같은 대조) + 파일 이름·디렉터리·모듈 낱말·시그니처 식별자(대소문자 무시). 흔한 경로 낱말(`tests`·`utils`·`core` ...)은 뺀다
- **E1** (§6.1.1): 수단·결과 낱말(기준선 A 의 DESIGN 단서 전부 - refactor·cleanup·simplify ... - 와 `fix`)이 **아닌** 이유 단서가 있다. 고른 라벨과 키워드 라벨이 같기를 요구하지 않는다 (위 표의 22건)
- E3("커밋 전체 목표만 말하는가")는 규칙으로 보지 않았다
- 이유 라벨은 건드리지 않는다. **test 100건(게이트 2 예측 파일과 비교)·검증 100건 모두 라벨이 r1 과 같았다**

규칙은 학습 300건 5겹 교차 검증(예측 라벨은 m2+c3)으로 골랐다. 후보는 이름 범위(함수만 / +파일 / +디렉터리·시그니처), 대조 방식(코드 표시 필요 / 대소문자 무시), E1(같은 라벨 키워드 / 아무 키워드 / 수단 낱말 제외) 조합이었다. 등급 정확도 최고(62.3%, 함수+디렉터리만·대소문자 무시)와 0.6%p 안쪽이면서, 가이드 v3 E2 목록을 그대로 쓰고 함수 이름 대조는 r1 그대로인 조합(61.7%)을 골랐다.

## 3. 결과

| | 등급 정확도 | EXPLICIT 예측 | precision | recall |
|---|---:|---:|---:|---:|
| r1, 학습 교차 검증 | 60.0% | 1 | 1.00 | 0.02 |
| r2, 학습 교차 검증 (고른 곳) | 61.7% | 44 | 0.50 | 0.34 |
| **r1, 검증** | **62.0%** | 2 | 1.00 | 0.10 |
| **r2, 검증** (보고용, 한 번) | **57.0%** | 13 | **0.385** | 0.24 |

- 학습에서는 +1.7%p 였는데 **검증에서는 -5.0%p** 다. 검증에서 r2 가 EXPLICIT 으로 바꾼 11건 중 맞은 것이 3건, 틀린 것이 8건이다
- 사람끼리도 한 라벨러가 EXPLICIT 이라 한 88건 중 다른 라벨러가 EXPLICIT 이라 한 것은 44건(0.50)이다 (학습). 원래 정밀하게 맞추기 어려운 경계다

검증에서 틀린 EXPLICIT 8건의 유형 (규칙을 고친 뒤 설명하려고만 봤다):

| 유형 | 건수 | 예 |
|---|---:|---|
| 커밋·PR·모듈 전체를 말하는 문장 (E3 실패) | 3 | "deprecate old docling-parse backends", "removes the legacy viz pipeline" |
| 저장소 이름·URL 속 낱말이 디렉터리 이름에 걸림 | 3 | `github.com/pandas-dev/pandas` 의 `pandas`, `browser-use` 의 `browser` |
| 이슈 본문의 일반 문장 | 1 | "But the task may catch this exception" |
| 함수를 가리키지만 이유가 아니라 호출자 변화 서술 | 1 | "callers of the advertised-as-deprecated ... now resolve" |

6건이 "이 레코드에 닿지 않는 문장" 이다. E3 와 저장소 이름 처리를 규칙으로 하지 못하면 이름 범위를 넓히는 것만으로는 정밀도가 오르지 않는다.

## 4. 결정과 이유

**r1 유지** (조장, 2026-10-18).
- 검증 precision 0.385 는 "EXPLICIT 은 가장 강한 주장이라 잘못 주는 것이 놓치는 것보다 나쁘다"(`classify/rules.py`, 가이드 §6.1)와 맞지 않고, 등급 정확도도 떨어졌다
- 더 엄격한 규칙을 다시 고르는 것은 하지 않았다 - 그 결과를 확인하려면 검증을 또 봐야 한다
- 이유 라벨은 r1·r2 가 같으므로 게이트 2 판정(`docs/meetings/gate-2.md`)에는 영향이 없다

## 5. 한계 (데이터셋에 적을 것)

- **분류기 등급은 보수적이다.** r1 은 EXPLICIT 을 거의 내지 않는다 (검증 2/100, test 0/100). 분류기 라벨의 등급 분포를 "데이터에서 이유가 명시된 비율" 로 읽으면 안 된다
- **EXPLICIT 비율은 사람 확정 500건 기준으로 보고한다** (EXPLICIT 110 / 500, `docs/reports/labels_main500.md`)
- 분류기 등급의 검증 정확도는 r1 62.0% 다 (등급별: EXPLICIT P 1.00 / R 0.10, INFERRED P 0.57 / R 0.70, UNKNOWN P 0.65 / R 0.82). 검증은 방식 선택에 여러 번 본 집합이라 낙관 쪽이다
