## 시도했다가 버린 것 / 발견 → 원인 → 조치 (§8.7 실패 기록 원칙)

**1. 가이드 v2의 "미달 블록 재라벨 고리" — 버리고 v3 한 번으로 끝냈다**
- 시도: 가이드 v2 §8.4.1은 블록의 처음 50건이 kappa 0.6 미만이면 "그 블록 정지 → 규칙 보강 → 버전 올림 → 그 50건 재라벨 → 재점검, 두 번째도 미달이면 §11"을 돌게 했다
- 결과: 세 블록이 모두 미달이었다
- 왜 버렸나 (`docs/evaluation.md` 사전 등록 "왜 지금 정하나"): 세 블록이 다 미달인 상태에서 고리를 돌면 (1) 개정할 때마다 기준이 바뀌어 한 데이터셋에 규칙이 여러 벌 생기고 (2) 끝나는 시점을 알 수 없으며 (3) "kappa가 나올 때까지 기준을 고쳤다"가 되어 kappa가 무엇을 재는지 흐려진다
- 대안: 개정을 v3 한 번으로 끝냈다. 일치한 81건은 v2 라벨 그대로, 갈린 69건만 두 사람이 v3로 각자 다시 판정, 점검은 독립 라벨인 51~100번으로, 결과는 **보고만** 한다. 클래스 병합(§11 대응)도 500건 안에서는 하지 않았다
- 남은 비용: 일치 81건 중 23건은 한쪽 이상이 ③(테스트 변화)을 첫 근거로 든 건이고 v3 규칙 2로는 성립하지 않는다. v2 기준의 정답으로 남는다 (가이드 §10.3)

**2. 불일치를 토론으로 확정하는 절차 — 제3자 판정으로 바꿨다 (ADR-019)**
- 원래: CHARTER §10.2와 가이드 §8.3은 불일치를 두 라벨러의 토론으로 확정하게 했다
- 바꾼 것: 그 블록에 들어가지 않은 제3자가 두 라벨 중 하나를 통째로 고른다 (A → hs, B → sj, C → jh)
- 결과에서 본 것 (`docs/reports/labels_main500.md`): 150건이 판정 파일의 저장 시각으로 5분 17초, 판정 사이 간격 중앙값 1초였다. 150건 중 UNKNOWN으로 간 건이 0건이고 등급이 강한 쪽을 고른 건이 136건이다. 판정 도구가 판정 이유를 묻지 않아 이유가 기록되지 않았다

**3. 필터 정밀도 — 규칙을 그 자리에서 고치지 않았다**
- 2차도 미달이었지만 PR #160에서는 필터 규칙을 고치지 않았다. 같은 24건으로 규칙을 고르고 같은 24건으로 효과를 세면 낙관적인 숫자가 나온다 (1차에서 57.0% → 64.0% 표본 안 추정이 그랬다)
- 규칙 후보만 순위를 매겨 남겼다. 1·2순위(NOISE_GENERATED 구현, NOISE_FORMAT 재등장 비교를 토큰 단위로)가 모두 효과를 내도 최대 8건이다

## 안 된 것과 이유
- **필터 정밀도 90% 미달** (76.0%). 후보를 다 고쳐도 표본 안에서 84이고, 새 표본으로 다시 재야 한다
- **v3 점검에서 블록 C 미달** (`reason` 0.376 / `grade` 0.233). 사전 등록대로 대응하지 않고 끝까지 갔다
- **사전 등록 최종 kappa(51번 이후 v3 쌍)는 대부분 0.6 아래다.** `reason` A 0.449 · B 0.655 · C 0.394, `grade` A 0.442 · B 0.548 · C 0.220. 51~100번 점검에서 0.6 이상이던 A·B도 101번 이후를 넣으면 내려간다
- **회수율 해석을 정하지 못했다.** 숫자만 냈다 (미정, 조장 판단)
- **H(ADR-016)를 아직 계산하지 않았다.** 분류기를 테스트에 돌리기 전에 낸다

## 배운 것
**점검 표본이 통과해도 전체가 통과하는 것은 아니다.** 51~100번 50건에서 A·B가 0.6을 넘었지만 51번 이후 전체로는 내려갔다. 가이드 §8.4.1이 "통과했다고 0.7이 보장되는 게 아니다"라고 적어 둔 그대로다.
**확정 절차의 속도와 방향은 숫자로 남겨야 한다.** 제3자 판정은 절차가 같다는 것으로 정답의 질을 보증하려던 것인데, 판정 시각과 고른 방향을 세어 보니 회수율이 판정에 크게 기댄다 (판정 전 38.0% → 판정 후 55.2%, 전부 약한 쪽이었다면 36.2%). 세지 않았으면 55.2%만 남았을 것이다.
