## 판정: 미달

### 근거
1. **기준 ① 미충족.** 우리 방식 60.0% 가 min(80%, H 80.8%) = 80.0% 에 20.0%p 못 미친다. 우리 방식의 95% 구간(50.2~69.1%) 상한도 80% 아래다
2. **기준 ② 충족.** 60.0% 가 max(A, B) + 10%p = 48.0% 를 12.0%p 넘는다
3. **ADR-016 결정 3: 둘 다 충족해야 통과한다.** ① 이 미달이므로 게이트 2 는 **미달**이다
4. 예외 2건의 영향 범위를 넣어도 ①·② 결과가 같다

## 해석 (사실만)

세 가지를 모두 적는다. 어느 하나만으로 결과를 요약하지 않는다.

1. **우리 방식은 기준선 A·B 보다 통계적으로 낫다.** 짝 비교에서 B 와 31 : 9 (p = 0.0007), A 와 36 : 9 (p = 0.0001) 이고, 95% 구간도 B(29.1~47.8%)·A(24.6~42.7%)와 겹치지 않는다
2. **그러나 사람 간 일치율 수준에는 못 미친다.** 같은 100건의 H 는 80.8% 이고 우리 방식은 60.0% 다
3. **test 의 절반이 UNK 라 "모두 UNK" 바닥이 50.0% 다.** 우리 방식은 이 바닥보다 10.0%p 높다. 기준선 A·B 는 바닥보다 낮다. **우리 방식이 B 를 앞선 것은 대부분 UNK 에서다** — UNK 정답 50건 중 우리 35건, B 15건을 맞혔다. 사람이 "근거 없음"으로 둔 건을 B 는 DESIGN·FEAT 로 채운다 (`gate2_test.md` §4)

## 미달 시 대응

### 사전 등록한 내용 (`docs/evaluation.md` "미달 시 대응", 조장 결정 2026-10-14, test 실행 전) — 그대로 옮김

- **test 는 한 번만 돌린다.** 결과를 본 뒤 방식·가중치·프롬프트를 바꿔 test 를 다시 돌리지 않는다
- **미달이어도 수치를 그대로 보고한다.** 정확도, 기준선 A/B 대비 차이(%p), 한계를 판정 기록(`docs/meetings/gate-2.md`)에 적는다
- **100개 저장소에 분류기를 적용할 때 분류기 라벨은 `reason.classifier_version` 으로 사람 확정 라벨과 구분하고, 근거 등급은 분류기가 낸 값을 그대로 둔다.** 데이터셋에서 사람 확정 500건과 분류기 라벨을 섞어 하나의 정확도로 보고하지 않는다. 핵심 산출물은 **확정 라벨 500건 데이터셋과 통계**로 한다. CHARTER §9 "최악의 경우 데이터셋 + 통계 + 분류기로 제출"과 같은 선이다
- **개선 시도는 test 가 아닌 새 표본에서만 한다.**

그 위의 규정: 하나라도 미달이면 CHARTER §9 버퍼 규정을 따른다 (8~9주차 확장 축소, 최악의 경우 7주차 산출물로 제출).

### 바뀐 계획 (이 판정으로 정한 것)

판정 기준 ①②, H, 사전 등록 본문은 바꾸지 않는다. 바뀌는 것은 100개 저장소 적용과 등급 처리다.

| 항목 | 사전 등록 | 바뀐 계획 |
|---|---|---|
| 100개 저장소 적용 버전 | 정하지 않음 | **모델만(`m2`)을 전체에** 적용하고, **저장소별 표본에만 LLM 포함 버전(`r1+m2+c3`)** 을 적용한다 |
| 라벨 구분 | `reason.classifier_version` 으로 사람 확정 라벨과 구분 | 그대로. 모델만 버전과 LLM 포함 버전도 **`classifier_version` 값으로 구분**한다. 실제 문자열은 모델만 `r1+m2`, LLM 포함 `r1+m2+c3+llm:deepseek-ai/deepseek-v4.1-flash` 다 (#180) |
| 성능 보고 | test 수치 그대로 | test 60.0% 는 **`r1+m2+c3` 의 값**이다. 모델만 버전의 성능은 **val 52.0%** (`classifier_val.md` §3, 학습 300건으로 학습)로만 보고한다. **test 는 재실행하지 않는다** |
| 근거 등급 | 분류기가 낸 값을 그대로 둔다 | 등급 규칙(EXPLICIT 판정) 수정은 **이유 라벨을 바꾸지 않는 범위에서만** 한다. 수정한 등급 규칙의 정확도는 **val 로만** 보고한다 |

- 모델만 버전의 val 52.0% 는 게이트 판정에 쓴 숫자가 아니다. 데이터셋에서 모델만 버전 라벨에 60.0% 를 붙이지 않는다
- 등급 규칙을 손대는 이유: 우리 방식은 test 에서 EXPLICIT 등급을 한 건도 내지 않았다 (정답 EXPLICIT 24, `gate2_test.md` §4). val 에서도 2건이었다 (정답 21, `classifier_val.md` §4). 등급은 판정에 쓰지 않으므로 이유 라벨이 그대로면 이 판정에 영향이 없다
- 개선 시도는 사전 등록대로 test 가 아닌 새 표본에서만 한다

## 한계

- **`gate2_test.md` §5 = `classifier_val.md` §5 그대로다.**
  - 기준선 B 와 우리 방식의 차이에는 맥락만 있는 게 아니다. 우리 LLM 은 가이드 요약(`CANDIDATE_GUIDE`)도 받고, B 는 사전 등록대로 `b1` 그대로다. "같은 가이드를 B 에 줬을 때"는 재지 않았다
  - 라벨러가 AI 보조 프롬프트(`docs/labeling_ai_prompt.md`)를 썼을 수 있다. c3 의 이유 정의는 그 문서 문구를 줄여 썼으므로 일치의 일부가 그 영향일 수 있다
  - test 의 이유 분포(집계, UNK 50건)는 실행 전에 봤다. 개별 레코드·예측은 보지 않았다
  - val 100건은 방식을 고르는 데 여러 번 봤다 (val 59.0% 는 낙관 쪽)
- **H 의 95% 구간이 72.0~87.4% 로 80% 를 포함한다.** ① 의 기준 80% 는 점추정 기준이다. 다만 우리 방식 구간 상한(69.1%)이 H 구간 하한(72.0%)보다도 낮아, ① 미달은 이 불확실성으로 바뀌지 않는다
- **100건이라 구간이 넓다.** 우리 방식 50.2~69.1%, B 29.1~47.8%, A 24.6~42.7% 다
- **비대칭이다** (ADR-016 한계). 분류기는 확정 라벨과, H 는 독립 라벨끼리 비교한다. 확정 라벨에 제3자 1인의 선택이 섞여 있어(ADR-019) "확정 라벨이 두 독립 라벨보다 정답에 가깝다"는 가정이 토론일 때보다 약하다

## §10.6 정리 시 반영할 것

- §10.6 의 A 는 게이트 2 미달인 test 60.0% (`r1+m2+c3`) 이고, 100개 저장소 전체에 붙는 모델만 버전에는 test 값이 없다(val 52.0%) — P × A 를 정리할 때(#129) 어느 A 를 쓰는지 정해야 한다.
