# ADR-013: 최상위 폴더 `eval/`·`tools/` 추가

- 날짜: **2026-09-14**
- 상태: 채택
- 관련 이슈: #37 (PR #38)
- 결정 경로: 조장(성제) 결정 → 이 ADR을 담은 PR의 리뷰(1명 필수, §8.2)로 팀 확인. 별도 회의록은 없다

## 맥락
- PR #38(#37)이 `eval/gate1.py`(게이트 1 측정·판정)와 `tools/label_cli.py`(라벨링 CLI)를 추가했다. 두 폴더 모두 2026-09-14에 처음 생겼다.
- CHARTER.md §8.1 저장소 구조도에는 두 폴더가 없다. 구조도는 `pipeline/`·`classify/`·`search/`·`web/`·`datasets/`·`docs/`·`tests/`만 나열한다.

## 결정
CHARTER.md §8.1 구조에 두 최상위 폴더를 추가한다.
- `eval/` — 평가·게이트 판정 스크립트. 라벨·파이프라인 산출물을 읽어 숫자와 판정을 낸다 (§9, §10)
- `tools/` — 사람이 쓰는 보조 도구. 파이프라인 단계가 아니다

## 이유
- **평가 스크립트와 라벨링 도구는 `pipeline/`·`classify/`·`search/` 어디에도 속하지 않는다.**
  - `eval/gate1.py`는 분류기가 아니라 분류기와 사람 라벨을 **재는** 쪽이다. `classify/` 안에 두면 측정 대상과 측정 도구가 섞인다.
  - `tools/label_cli.py`는 사람이 라벨을 입력하는 도구다. 데이터가 흐르는 파이프라인 단계가 아니다.
- **§8.1에 없는 폴더가 늘어나면 문서와 레포가 어긋난다.** 새 팀원과 각자의 Claude는 CHARTER.md를 기준으로 파일을 찾는다 (§8.5, §16). 구조도에 없는 폴더는 "있으면 안 되는 것"처럼 보이거나, 다음 사람이 비슷한 폴더를 또 만든다.

## 대안과 버린 이유
- **기존 폴더 안에 둔다** (`classify/eval_gate1.py`, `pipeline/label_cli.py` 등) — 버림. 위 "이유" 첫째 항목. 담당 영역 경계(§6.1, CLAUDE.md)도 흐려진다. `classify/`는 희수 영역인데 게이트 측정·라벨링 도구는 평가 담당(성제) 영역이다.
- **`scripts/` 한 폴더로 묶는다** — 버림. 평가(숫자를 내는 것)와 도구(사람이 쓰는 것)는 입력·출력·테스트 방식이 다르다. 한 폴더에 섞으면 무엇이 게이트 판정에 영향을 주는 코드인지 구분이 어렵다.

## 영향
- CHARTER.md §8.1 구조도에 두 폴더와 현재 파일 추가, §5 표에 행 추가 (v1.8). **이 PR에서 반영.**
- 스키마·분류 체계·파서 인터페이스 변경 없음.
- **이 PR에서 하지 않은 것 (후속):**
  - `pyproject.toml`의 `[tool.setuptools.packages.find] include`가 `pipeline*`·`classify*`·`search*`만 담는다. `eval`·`tools`는 설치 패키지에 들어가지 않는다. pytest·CI는 저장소 루트에서 돌아서 지금은 영향이 없다. 설정 변경이라 문서 PR과 분리한다.
  - `README.md` 구조 표에 두 폴더가 없다.
  - `CLAUDE.md` 담당 영역 표의 성제 경로가 "평가 스크립트"로만 적혀 있고 `eval/`·`tools/` 경로가 없다.
- 새 최상위 폴더를 또 만들 때는 이 ADR처럼 §8.1 갱신을 함께 한다.
