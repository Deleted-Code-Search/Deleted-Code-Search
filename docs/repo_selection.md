## 1. 무엇을 걸렀나

검색: `language:Python is:public archived:false stars:>=1000` (별 수 내림차순 100개)
\+ §4.3의 초기 후보 예시 10개는 검색 결과와 무관하게 항상 평가했다.

| 단계 | 기준 | 제외 |
|---|---|---:|
| 라이선스 | MIT / Apache-2.0 / BSD 계열만 (§4.3 ②, ADR-007) | 42 |
| 규모 | 커밋 1,000개 이상 (§4.3 ⑤) | 19 |
| 활동 | 최근 1년 커밋 있음 | 2 |

후보 43개의 라이선스: MIT 22 / Apache-2.0 14 / BSD-3-Clause 7.

**별 수는 점수에 넣지 않았다** (ADR-006). 검색 하한으로만 쓰고, 순위는 PR 문화·이슈 참조·규모로 낸다.

## 2. 무엇을 쟀나

저장소마다 **최근 1년 커밋 표본 30건**(병합 커밋·봇 커밋 제외)에 대해:

- `pr_ratio` — 표본 중 **머지된 PR**에 속한 커밋 비율. 열린 PR은 세지 않는다. (§4.3 ③, 목표 ≥ 0.70)
- `issue_ref_ratio` — 커밋 메시지 + 머지된 PR 제목·본문에 `#번호`가 있는 비율. (§4.3 ④)
  `Merge pull request #123`, `... (#123)` 같은 **PR 자기 번호는 이슈 참조로 세지 않는다.**
  이걸 빼지 않으면 스쿼시 머지를 쓰는 저장소가 전부 100%로 나온다.
- `score = 0.5·pr_ratio + 0.3·issue_ref_ratio + 0.2·규모` (규모는 1,000커밋 0 → 50,000커밋 1.0 로그 스케일)

왜 이 둘인가: 우리가 필요한 건 삭제 코드가 아니라 **삭제 이유**다. 이유는 PR 본문과 연결된 이슈에 남는다.
PR 없이 main에 직접 푸시하는 저장소는 커밋 메시지 한 줄이 전부라 이유 회수율이 낮을 수밖에 없다.

## 4. 읽을 때 주의할 것

**① §4.3 예시 10개가 어떻게 됐나**

| 저장소 | 결과 |
|---|---|
| django, scikit-learn, pydantic, pandas, requests | 상위권 후보 (2·3·4·6·16위) |
| fastapi | 25위, pr=1.00 — 아래 ②를 반영한 뒤의 값이다 |
| httpx | 36위, 표본 6건뿐 (최근 1년 커밋이 적다). 비율의 신뢰구간이 넓다 |
| sqlalchemy | 40위, **pr=0.03**. 표본 30건 중 28건을 메인테이너 한 사람이 썼고, 머지된 PR을 거친 건 1건뿐이다. PR 본문이 없으니 이유 회수도 어렵다 |
| flask | 41위, **pr=0.27**. 표본 30건 중 27건을 메인테이너 한 사람이 썼고, PR을 거친 건 8건 |
| celery | **제외** — GitHub가 라이선스를 `NOASSERTION`으로 본다. 실제 라이선스를 사람이 확인하면 되살릴 수 있다 |

sqlalchemy·flask의 낮은 값은 측정 오류가 아니라 실제 관행이다. 별 수로 골랐으면 둘 다 상위에 들어왔을 것이고,
이유 회수율은 낮았을 것이다. ADR-006이 노린 게 이 차이다.
(sqlalchemy가 GitHub PR 대신 다른 리뷰 도구를 쓰는지는 확인해 볼 것 — 쓴다면 그쪽에 이유가 있을 수 있다.)

**② 봇 커밋을 빼야 한다**
1차 측정에서 fastapi는 pr=0.50이었다. 표본 30건 중 28건이 `latest-changes[bot]`·`dependabot[bot]` 등
릴리스 노트·의존성 봇이 PR 없이 직접 민 커밋이었다. 봇을 뺐더니 pr=1.00 (37위 → 25위).
지금 스크립트는 봇을 표본에서 제외한다. **다른 지표를 만들 때도 같은 함정을 확인할 것.**

**③ 상위권에 검증이 필요한 저장소가 섞여 있다**
`NousResearch/hermes-agent`(별 24만인데 이력이 33k 커밋), `bytedance/deer-flow`, `mvanhorn/last30days-skill`,
`github/spec-kit`, `crewAIInc/crewAI` 같은 최근에 뜬 저장소는 PR·이슈 관행 점수는 높지만
**"버려진 코드"가 쌓일 만큼의 역사가 있는지**는 별개다. `TheAlgorithms/Python`은 예제 모음이라
삭제가 실제 설계 판단이 아닐 수 있다. 킥오프에서 눈으로 확인하고 뺄 건 뺀다.

**④ 게이트 미달 6개도 후보로 남겼다**
`pr_gate_pass=false`(pr < 0.70): MetaGPT 0.50, PayloadsAllTheThings 0.53, sqlalchemy 0.03,
flask 0.27, graphify 0.00, screenshot-to-code 0.00.
§4.3 ⑥이 "첫 실험 후 기준 재조정"이라, 지금 잘라내면 재조정할 표본이 사라진다.
하드 컷이 필요하면 `--enforce-pr-gate`.

**⑤ 표본 30건은 최근 1년의 단면이다**
저장소 전체 역사의 관행이 아니라 지금 관행을 잰 값이다. 오래된 저장소는 과거에 PR을 안 썼을 수 있다.
2주차 이유 회수율 측정에서 이 값과 실제 회수율이 얼마나 맞는지 보고 §4.3 ⑥에 따라 기준을 고친다.
